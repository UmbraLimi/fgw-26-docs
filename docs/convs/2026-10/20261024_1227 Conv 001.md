## Progress
Conv 001 was a harness conv — no product work. It opened on an unplanned thread: the operator caught
`/r-start` closing with a free-text question, violating the CLAUDE.md A/B rule, and pressed that
"I'll do better" was hand-waving since the rule already existed and still failed. That produced the
principle driving both pieces of work: an enforcement that lives *outside* the judgment that lapsed.
First a Stop hook for the A/B rule; then, reusing the same insight, the long-open turn-capture hopper
item was ruled do-now and built the same way. Before building capture, surveyed all three siblings'
`/r-end` dialogue handling (FPS: none; Peerloop: manual `.scratch/conv-turns.md` + a separate
transcript viewer; SPT: a `UserPromptSubmit` hook) and chose SPT's auto-capture model. Both hooks were
confirmed to load mid-session via the file watcher (no restart). Capture only caught this conv's tail
because it was built mid-conv; Conv 002 onward gets full capture from `/r-start`.

## Decisions
- DEC-001-1 — Enforce the A/B question format with a Stop hook, not willpower.
- DEC-001-2 — Capture the operator's turns verbatim via a UserPromptSubmit hook.

## Learnings
- **Context:** both hooks were added to `.claude/settings.json` during the running session.
  **Learning:** the file watcher picks up settings-file hook edits live — verified empirically for
  both (Stop hook via a probe; capture hook by observing a captured prompt), no restart needed.
  **Pattern:** a hook you just wired can be confirmed the same session with a one-line probe.
- **Context:** the A/B rule was already in CLAUDE.md and was still violated this conv.
  **Learning:** a rule that depends on the model's own live discipline is not reliably followed;
  enforcement must be a check outside that discipline. **Pattern:** when a standing rule lapses,
  prefer a hook over re-asserting the rule.
