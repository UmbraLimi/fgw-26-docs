## Learnings
- **Preview-viewport floor.** The Claude-in-Chrome `resize_window` would not take the tab's `innerWidth`
  below ~586px this session, so true-phone widths couldn't be screenshotted — responsive sizing was verified
  by JS measurement (`getBoundingClientRect`) instead. Keep a measurement fallback for responsive checks.
- **Fix the tool, not the prose.** When liked prose produced a thin auto-extracted FAQ answer, the fix was an
  extractor rule (read a lead-in section through to the next H2), not a rewrite — it decouples prose style
  from extract completeness.
- **FAQPage compliance drives extraction.** FAQ structured data must match visible page content, so
  hand-authored frontmatter answers were rejected in favour of extracting from the body.
