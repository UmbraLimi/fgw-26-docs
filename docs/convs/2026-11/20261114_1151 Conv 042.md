## Progress
The conv set out to give each guide/article an O'Reilly-style monochrome animal illustration, and became a
long design + craft exploration that pivoted twice. First pivot (craft): automated photo→line-art tracing
was tried hard (a dragonfly head macro, a pimpleback mussel photo) and failed — it *reproduces* a specimen's
3-D/tonal noise and cannot *interpret* which features are diagnostic, so even simple subjects read as
complex. The operator named the real target (a naturalist's narrative drawing), which resolved into the key
insight: feed the pipeline input where the interpretation is already done — public-domain **line engravings**
(not photos, not AI, not tonal lithographs). Second pivot (legal): the operator worried about O'Reilly; the
analysis separated copyright (clean — the same PD well) from trade dress (the real but low risk, aggravated
by software + woodcut-animals being O'Reilly's niche) — managed, not avoided. The first image (Lister *Conus
marmoreus*) was cropped by the operator (a square detail on the diagnostic feature) and gently cleaned (a
heavier flat-field washed detail, rejected). Then the data model: co-located `provenance.json` per image
folder + one central Zod schema (drift = build error), one source → many kept treatments, single-repo (the
docs/site split rejected for cross-repo duplication). Built + rendering on the Trust guide (square tile +
colophon), verified in dev. Closed with /r-commit then /r-hopper (2 promoted, 1 dropped).

## Learnings
- **Context: automated image processing for illustration. Learning:** tracing *reproduces*, it cannot
  *interpret* — it has no model of what is diagnostic, so it renders all the incidental 3-D/tonal noise; the
  fix is input a human already interpreted (a line engraving), not better thresholds. **Pattern:** when a
  pipeline's output stays "too busy" at every parameter, question whether the *input* carries the
  abstraction you want.
- **Context: the operator could not see images. Learning:** images shown via the Read tool render to the
  model, not to the operator's terminal (VS Code's integrated terminal can't display them inline) — the
  operator must open the file. Surfaced mid-conv; now I `open <path>` for them whenever I generate one.
- **Context: Astro content-store cache. Learning:** a `content.config.ts` schema change is not picked up by
  a running dev server via HMR, and even a restart can reuse a stale `.astro/data-store.json`; deleting it
  forces the rebuild. Verified by curling the rendered HTML, not just `astro sync`.
