## Progress
The session opened as a product question — why does launching `fgw` prompt to add/trust the folders, and
can it be turned off? Root cause was the v2.1.325 `--add-dir` trust-prompt change against two untrusted
reference repos. The operator chose `additionalDirectories` (file-read access, no prompt, no config load —
right for read-only reference) over pre-trusting via `hasTrustDialogAccepted`. The operator then caught
that a caveat I'd "surfaced inline" had in fact been routed nowhere, which drove the governance work: a
tightened Surfacing rule plus a hard-enforcement Stop hook keyed on the deliberate disposition vocabulary
(not the bare word "routing", which saturates prose). Notably, all of this substantive work happened
**before** `/r-start` — the conv was opened mid-stream, then `/r-commit`, `/r-hopper` (6 items), and
`/r-end` ran to close it.

## Learnings
- **Lifecycle / capture / gap.** Operator-substantive turns done before `/r-start` are not captured by
  `capture-turn.sh` (it keys on `.conv-current`, absent until the conv opens), so a conv opened mid-stream
  has no verbatim dialogue record for its richest exchanges. See carried findings.
- **Enforcement / hook design / pattern.** A Stop hook that enforces a prose rule must key on a
  *deliberate* marker (here, disposition vocabulary; for the A/B guard, the `👉👉👉` anchor), never on a
  common word, or it fires on every turn that merely discusses the rule.
