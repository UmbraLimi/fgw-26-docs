## Learnings
- **Astro view transitions + anything script-driven.** The site uses `<ClientRouter>`, so GA page_views
  and the Turnstile widget (and any third-party script) must re-init on `astro:page-load` — the one-time
  `config`/`api.js` auto-run misses client-side navigations. Pattern: explicit init + an `astro:page-load`
  listener, **verified by a real client-side nav**, not just a direct load.
- **Turnstile `110200` = hostname not in the widget's allowlist.** A fresh widget fails on any host not
  listed — including the `workers.dev` prod URL used for testing. The apex + `www` must be added before
  cutover or the live form breaks.
- **Turnstile can't be fully verified by automation** — the managed widget correctly *challenges* an
  automated browser, so the human happy-path is the operator's test (which here surfaced the real `110200`
  config bug). Verify what you can without it (enforcement: tokenless → 403), hand the human path over.
